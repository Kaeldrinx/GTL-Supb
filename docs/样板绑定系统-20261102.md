# 样板绑定系统 — 2026-11-02

## 定位

`IPatternAssemblyHatch` + `PatternAssemblyPartMachine` 实现"样板 → 具体配方"的绑定，
让样板总成仓能驱动多方块机器按绑定配方精确合成，并支持逐槽独立供料。

## 绑定契约

### 解析优先级

1. 样板 NBT 的具体配方 id（`gtlsupb.recipe_id`）——精确绑定；
2. 配方类型元数据（`gtlsupb.recipe_type` 或 gtlcore 的 `gtlcore.patternQuickUploadRecipeTypes`）——类型级；
3. 无绑定 → 回退整机输入匹配（全配方池）。

### 优先级与冲突

- 多个槽位绑定同一配方：各槽位独立供料、独立核算，互不瓜分。
- 同一槽位重复写入：以最后一次为准（映射重建覆盖）。
- 绑定 vs 机器模式：绑定优先，不切换玩家模式；但绑定配方类型必须属于机器支持的模式列表，
  跨类型绑定一律拒绝。

### 动态更新与解绑

- 样板内容指纹变化 → 重建"槽位 → 配方"映射，并 `markLastRecipeDirty()` + 唤醒控制器。
- 样板被取出 → 该槽位自动解绑；全部解绑 → 回退全池匹配。
- 配方表变动导致解析失败 → 缓存保留 100 tick 后自动重试。

### 失败回退

| 失败类型 | 行为 |
|---|---|
| 绑定类型不被机器支持 | 拒绝该条绑定，记诊断日志 |
| 全部绑定被拒绝 | 回退全池匹配 |
| 绑定暂时缺料/条件不满足 | 不回退（避免样板间抢料），保持等待 |
| 具体配方持续不可执行（60 秒） | 降级为按绑定类型搜索（仍不切模式） |

## gtlcore 类型元数据兼容

`Ae2PatternHelper` 写入绑定时同步写入 gtlcore 兼容键：

```
gtlcore: { patternQuickUploadRecipeTypes: ["<ns>:<type>"] }
```

- 使本模组编码的样板能被 gtlcore 的快速上传选择器/样板 tooltip 识别。
- 精确绑定仍以 `gtlsupb.recipe_id` 为唯一运行期依据，类型只用于降级与展示。
- 读取时优先 `gtlsupb.recipe_type`，缺失时回落 gtlcore 键（`readGtlcoreRecipeTypeId`）。
- 倍率重建（`copyRecipeBinding`）会单独搬运 `gtlcore` 根键，避免丢失。

## 逐槽供料

- 逐槽供料是本模组的**模拟记账**（AE2 样板槽原生只存样板、不存原料），解决多样板共用
  输入池时的互相抢料。
- 它只在"样板 → 具体配方"精确绑定时有意义；若改成类型级模型应整层移除，回到共享输入池。
- 逐槽并行上限见 `getIndependentSlotParallelCap`。

## 验证

- 绑定/解绑/降级逻辑由 `MutableRecipesLogic` 的绑定分支承载，回归经 `spotlessApply build`。
- 实机要点：样板取出后回退全池、误绑被拒、绑定失效 60 秒后按类型继续。
