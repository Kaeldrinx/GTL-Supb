# 绑定系统通用化 — 任务清单（阶段 5 / 6）

目标：让“样板绑定”这套机制在**任意 GT 机器**上可用，而不只局限于本项目自有机器（`MutableRecipesLogic` 体系）。
核心设计：**仓是“槽位与绑定”的唯一真相源；机器侧只通过注入层向它查询**，别家机器无需实现本项目接口。

| 2 | 绑定配方白名单（精准匹配通用化） | 同上：`collectPatternBoundRecipes()` 收集绑定集合，逐条 `isSupportedBoundRecipeType` + 输入匹配后作为唯一候选集 |

## 二、关键 API 事实（**以 `libs/gtceu-1.20.1-1.4.4.jar` 的 javap 为准**，参考源码不可信）

- `RecipeLogic#searchRecipe()` 是 **protected**（注入按名匹配即可）；
- **不存在 `checkRecipe(...)` 方法**（参考源码里的写法在本依赖中不存在）；
- 存在 `RecipeLogic#markLastRecipeDirty()`（public）→ 用于让 `findAndHandleRecipe()` 的 `lastRecipe` 复用路径失效；
- `RecipeLogic` 字段：`protected GTRecipe lastRecipe`、`protected boolean recipeDirty`；
- `IRecipeLogicMachine`：`getRecipeType()` / `getRecipeTypes()` / `getRecipeLogic()`；
- `MultiblockControllerMachine#getParts() → List<IMultiPart>`；
- `GTRecipeType#getLookup()` → `GTRecipeLookup`（`getRecipeIterator(machine, predicate)`）。

## 三、阶段 5 待办（按机器分批，改一处 → 构建 → 实测 → 再下一处）

1. **并行**：`ParallelLogic.getParallelAmount(...)` / 各机器的 `getParallelLimit()` 与线圈倍率逻辑不同，需逐类确认；注入前先确认“机器自身并行”与“绑定配方”是否冲突。
2. **批处理**：自有机器用 `IBatchProcessingMachine` + 侧边栏配置项；别家机器需自行实现该接口（不建议注入）。
3. **无线电力**：自有机器用 `IWirelessElectricMultiblockMachine`；别家机器需接管其能量仓（侵入性强，优先级最低）。
4. **显示一致性**：模式不再切换后，建议在 Jade / 机器状态里显示“实际执行类型 = 绑定类型”。

**排序建议**：1 → 4 → 2 → 3（按“收益 / 侵入性”比）。

## 六、过程纪律（本项目已踩过的坑）

- **同一文件不要在同一个批次里发多个 `replace`**：已发生两次“后写覆盖前写”导致改动静默丢失（import 段最易中招）——每次改完必须回读或 javap 核对。
- **任何 GTCEu/GTLCore API 结论必须先 javap 依赖 jar**（参考源码与依赖版本存在签名差异）。
- Mixin 注入失败只在**运行时**报错（`Mixin apply failed` / `InvalidInjectionException`），构建不会暴露：每次改动后需在实例日志中确认。
