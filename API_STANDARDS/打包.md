# 构建与打包

本文件定义 GTLSUPBJAVA 模组的构建、产物验证与部署流程。**仅在用户要求「构建 / 打包 / 发布」时读取与执行**（`执行规则.md` 规则 18）。

---

## 一、构建

### 前置条件

| 条件 | 判定方式 |
|---|---|
| Gradle 守护进程已停止 | `.\gradlew.bat --stop`（必要时结束残留 `java` 进程，避免 Loom 缓存损坏） |
| JAVA_HOME 指向 temurin-17 | `$env:JAVA_HOME='C:\Users\Administrator.DESKTOP-N0QCVKS\.jdks\temurin-17'` |
| 沙箱已关闭 | `java` 会写 `C:\ProgramData\Oracle\Java\...`，沙箱内构建会被拦截 |
| 依赖可解析 | `libs/` 本地化依赖 + 网络（若需下载，先按规则 23 提示开代理） |

### 统一命令

```powershell
cd E:\GTL\GTLSUPBJAVA
$env:JAVA_HOME='C:\Users\Administrator.DESKTOP-N0QCVKS\.jdks\temurin-17'
.\gradlew.bat --stop
.\gradlew.bat spotlessApply build
```

- `spotlessApply` 自愈代码格式（import 顺序 + eclipse 格式 + 去未用 import）；跳过会触发 `spotlessJavaCheck` 失败。
- `build` = 编译 + 重映射 + 打包（jar + sources jar）。
- **成功判定**：日志出现 `BUILD SUCCESSFUL`。PowerShell 管道把 javac 警告（stderr）误报为 `NativeCommandError` 导致的非零退出码不代表构建失败，不得据此误判。

### 构建约束（原 `build.gradle` 内注释，按规则 31 迁出）

| 约束 | 原因 |
|---|---|
| `-AdisableTargetValidator=true` | gtladditions 注入要同时覆盖 `GTLAddMultiRecipesTypesLogic` 与 `GTLAddMultipleTypeRecipesLogic` 两个命名变体，编译期只挂其中一份 jar，另一个 target 必然解析不到；关闭校验后由注入自身 `require = 0` 兜底 |
| gtladditions 用 `compileOnly files('libs/gtladditions-compile-only.jar')` | 仅供 Mixin 注解处理器解析 `@Mixin(targets = "com.gtladd.gtladditions...")`，运行时由实例的 jar 提供 |
| ftb-quests 用 `compileOnly files('libs/ftb-quests-forge-2001.4.22.jar')` | 避免 Loom 对同一依赖重复 remap，运行时由实例 `mods/` 提供 |
| `recipeSafetyTest` 的 classpath 只挂 `sourceSets.test.output` + `sourceSets.main.output` | 挂 `testRuntimeClasspath` 会拉起整套 Minecraft 与全部模组运行时，离线环境无法解析，且与本测试无关 |
| `tasks.named('test') { enabled = false }` | 本工程不使用 JUnit，标准 test 任务只会解析整套运行时后空跑 |
| `mixinConfigs` 只声明 `gtlsupb.mixin.json` | 该名字对应 `src/main/resources/gtlsupb.mixin.json`；`refmap` 字段由 `remapJar` 在打包时注入，源文件里不写 |
| Mixin `@Overwrite` 缺 Javadoc 会打印 `@Overwrite is missing javadoc comment` | 属提示级消息，构建仍 `BUILD SUCCESSFUL`；按规则 31 不补注释 |

## 二、产物

```text
E:\GTL\GTLSUPBJAVA\build\libs\
├── GTLsupb-<版本>.jar            # 主产物（remap 后，可部署）
└── GTLsupb-<版本>-sources.jar    # 源码包
```

版本号来源：`gradle.properties#mod_version`（当前 `4.8.5`）。

## 三、产物验证（规则 14，不可跳过）

构建退出码 0 不代表产物正确。必须：

1. **解包核对本次改动内容**：用 `Add-Type System.IO.Compression.FileSystem` + `ZipFile::OpenRead` 列 jar 内条目，确认本次新增/修改的类、资源、语言键存在（且不是旧产物残留）。
2. **字节码核对**（关键类改动时）：用 `javap -p` 确认新增方法签名（如 `RecipeCalculationHelper.findFeasibleBatch`）。
3. **语言键集核对**：`zh_cn.json` 与 `en_us.json` 键集一致。

验证命令示例：

```powershell
Add-Type -AssemblyName System.IO.Compression.FileSystem
$zip = [System.IO.Compression.ZipFile]::OpenRead('E:\GTL\GTLSUPBJAVA\build\libs\GTL-Supb-4.8.jar')
$zip.Entries | Where-Object { $_.FullName -match 'RecipeCalculationHelper|ZeroEnergyMultiTypeLogic' } | ForEach-Object { $_.FullName }
$zip.Dispose()
```

## 四、版本号

- 格式：`主.次.阶段.序号`（如 `3.4.beta.9`），定义于 `gradle.properties#mod_version`。
- 缺陷修复/小功能递增 `beta.N` 序号；功能集变更再提升阶段。
- 必须同步到：`gradle.properties`、`启动上下文.md`、`变更历史.md`。
- **禁止沿用旧版本号发布**。

## 五、部署（到游戏实例）

1. 把 `build\libs\GTLsupb-<版本>.jar` 复制到实例 `mods\`；
2. **部署前删除同 MOD ID 的旧 JAR**（`copy` 覆盖不够，可能重复加载崩溃）；
3. 记录部署 JAR 的 SHA-256；
4. 启动游戏读日志确认：模组加载成功、无 mixin 应用失败、无类加载错误。

## 六、发布后

1. 把构建版本、日期、产物路径、SHA-256 写入 `变更历史.md`；
2. 同步 `启动上下文.md` 的版本号与产物状态；
3. 游戏内行为验证结果由玩家在实例中确认后回填。
