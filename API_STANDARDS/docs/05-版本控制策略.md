# 05 · 版本控制策略

> 目标：**版本可追溯、升级可预期、依赖可复现。** 分四层管理：模组版本、协议版本、依赖版本、数据兼容。
> 对齐行业 SemVer（语义化版本）与锁文件实践，同时适配 Minecraft 模组生态现状。

---

## 1. 模组版本（SemVer 主版本 · 次版本 · 修订版本）

- **MUST**：模组版本定义于 `gradle.properties` 的 `mod_version`，唯一事实源。
- **MUST**：遵循语义化版本：
  - **主版本（Major）**：破坏性 API 变更 / 存档不兼容；
  - **次版本（Minor）**：向后兼容的新功能；
  - **修订版本（Patch）**：向后兼容的缺陷修复。
- **MAY**：预发布版本用 `-alpha.N` / `-beta.N` 后缀（如 `3.4.beta.8`），正式版移除后缀（如 `1.5.7`）。

**项目正例**：
- [GTLSUPBJAVA gradle.properties](../GTLSUPBJAVA/gradle.properties)：`mod_version=3.4.beta.8`（见 [build.gradle](../GTLSUPBJAVA/build.gradle) 引用）。

## 2. 协议版本（网络兼容）

- **MUST**：网络通道定义 `PROTOCOL_VERSION` 字符串，客户端/服务端双向严格匹配（`v -> v.equals(PROTOCOL_VERSION)`）。
- **MUST**：**协议不兼容变更**（字段删改、语义变化、注册顺序变化）必须递增 `PROTOCOL_VERSION`。
- **SHOULD**：协议版本变化记录在变更日志，注明兼容矩阵。

**项目正例**：[GTLSupbNetworkHandler.java](../GTLSUPBJAVA/src/main/java/com/gtlsupb/gtlsupb/network/GTLSupbNetworkHandler.java) `PROTOCOL_VERSION = "1"` 与双向严格匹配。

## 3. 依赖版本（可复现构建）

- **MUST**：所有依赖版本集中声明于 `gradle.properties`（`gtceu_version`、`jei_version`、`jade_version` 等），build.gradle 引用变量，禁止散落魔法版本号。
- **MUST**：外部依赖使用精确版本（锁定），升级需人工确认并回归。
- **SHOULD**：本地依赖 jar（libs/ 目录，如 gtlcore、gtceu）在升级前用参考项目对比验证（对照 gtlcore 实现进行行为核对）。
- **SHOULD**：构建环境固定（JDK 版本在 gradle.properties 声明，如 `org.gradle.java.home`）。

**项目正例**：[GTLSUPBJAVA gradle.properties](../GTLSUPBJAVA/gradle.properties) 全部依赖集中管理；[GTLSUPBJAVA libs](../GTLSUPBJAVA/libs) 本地锁定关键 jar。

## 4. API 演进规则

| 变更类型 | 要求 |
| --- | --- |
| 新增字段（可选） | **SHOULD** 用 has 标记 + 长度前缀，旧端安全忽略（向后兼容） |
| 新增能力/接口 | **SHOULD** 新增 `PartAbility` 与能力接口，不动既有接口 |
| 废弃接口 | **MUST** `@Deprecated` 标注 + Javadoc 说明迁移路径，保留一个迁移期 |
| 破坏性变更 | **MUST** 递增主版本，并在 CHANGELOG 显式声明 breaking changes |
| 数据包 ID 顺序 | **MUST** 不改变历史注册顺序；仅允许尾部追加 |

**项目正例**：[C2SWAPConnectionPacket.java](../GTLSUPBJAVA/src/main/java/com/gtlsupb/gtlsupb/network/C2SWAPConnectionPacket.java) 可空目标字段 `writeBoolean(hasTarget)` 模式。

## 5. Git 工作流与发布

- **MUST**：分支模型：`main`（稳定）/ `develop`（集成分支）/ `feature/*`（功能）/ `release/*`（发布候选）。
- **MUST**：版本 tag 与 `mod_version` 一致（如 `v1.5.7`），发布即打 tag。
- **SHOULD**：发布包（jar）记录构建信息（时间戳、commit、源码版本）于 `mods.toml` 或构建产物说明。
- **SHOULD**：CHANGELOG 按版本组织，条目含类型（feat/fix/refactor/breaking）与关联 API。

## 6. 存档/数据兼容（Minecraft 特有）

- **SHOULD**：存档数据（玩家持久化、NBT）变更设计迁移路径，旧存档读取失败要安全降级而非崩溃。
- **SHOULD**：涉及世界生成/维度注册的变更评估旧档兼容性（如维度类型 [private_dimension_type.json](../GTLSUPBJAVA/src/main/resources/data/gtlsupb/dimension_type/private_dimension_type.json) 的注册变更影响）。

---

## 7. 检查清单

- [ ] mod_version 在 gradle.properties 单一事实源，符合 SemVer；
- [ ] 协议变更递增 PROTOCOL_VERSION；
- [ ] 依赖版本全部集中声明且锁定；
- [ ] 新字段向后兼容（has 标记），破坏性变更走主版本递增；
- [ ] 废弃接口有 @Deprecated + 迁移说明；
- [ ] 发布打 tag、CHANGELOG 更新。
