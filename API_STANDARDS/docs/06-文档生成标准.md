# 06 · 文档生成标准

> 目标：**文档与代码同源、读文即知契约、双语面向玩家、工具化生成。**
> 文档三件套：代码内注释（开发者）、语言文件（玩家）、接口文档（契约）。

---

## 1. 代码内文档（开发者）

### 1.1 注释原则

- **MUST**：注释解释**为什么**（动机、约束、陷阱），不赘述**是什么**（代码本身自明）。
- **MUST**：注释精简，不过多（单条注释 ≤ 3 行为宜），避免噪声。
- **MUST**：注释使用中文（团队语言约定）。
- **MUST**：注释与实现同步更新，禁止与行为脱节的陈旧注释。

### 1.2 Javadoc 要求

| 位置 | 要求 |
| --- | --- |
| 类 | 职责、使用场景、关键约束、触发链路（数据包类必须写） |
| 公开方法 | 入参语义、返回值语义、边界值、失败行为 |
| 常量 | 语义与单位（如动作码含义） |
| 接口 | 契约：能力来源、计算规则、边界条件 |

**项目正例**：
- 数据包契约注释：[C2SWAPConnectionPacket.java](../GTLSUPBJAVA/src/main/java/com/gtlsupb/gtlsupb/network/C2SWAPConnectionPacket.java) 类注释完整描述触发链路、校验规则、回发行为；
- 能力契约注释：[IBatchProcessingMachine.java](../GTLSUPBJAVA/src/main/java/com/gtlsupb/gtlsupb/api/machine/IBatchProcessingMachine.java)、[ILimitedDurationMachine.java](../GTLSUPBJAVA/src/main/java/com/gtlsupb/gtlsupb/api/machine/ILimitedDurationMachine.java)。

### 1.3 反模式

- ❌ 逐行注释"这行代码做什么"；
- ❌ 注释只写"处理 XX"却不说明约束与边界；
- ❌ 删除代码时把代码注释掉留作历史（应直接删除）。

## 2. 语言文件（玩家可见文案）

- **MUST**：所有 GUI 文本、Tooltip、提示消息走语言文件（`assets/<modid>/lang/zh_cn.json` + `en_us.json` 双语），禁止硬编码显示文案。
- **MUST**：翻译键命名 `modid.分类.语义`（如 `gtlsupb.wap.connection.jumped`），分类与代码语义一一对应。
- **MUST**：占位符统一（`%s`/`%d`），数字单位带上下文（如 `可用液态冰：%s mB`）。
- **MUST**：中英双语键集保持一致，禁止缺键。
- **SHOULD**：Tooltip 文案精简、说明机制而非显而易见的内容（参考 [zh_cn.json](../GTLSUPBJAVA/src/main/resources/assets/gtlsupb/lang/zh_cn.json) 风格）。

**项目正例**：[zh_cn.json](../GTLSUPBJAVA/src/main/resources/assets/gtlsupb/lang/zh_cn.json) 与 [en_us.json](../GTLSUPBJAVA/src/main/resources/assets/gtlsupb/lang/en_us.json) 双语对照。

---

## 3. 接口文档（契约）

- **MUST**：每个网络数据包在类 Javadoc 中说明：触发端、请求字段、服务端校验、回发内容——**类注释即接口文档**。
- **MUST**：每个能力接口在 Javadoc 中说明：能力来源、计算规则、边界值。
- **SHOULD**：对外 HTTP API 使用 OpenAPI/Swagger 描述（paths、schemas、errorCodes），由契约文件生成文档，禁止手写与实现脱节的接口文档。

**项目正例**：数据包契约注释范式见 [C2SWAPConnectionPacket.java](../GTLSUPBJAVA/src/main/java/com/gtlsupb/gtlsupb/network/C2SWAPConnectionPacket.java)；对外文档模板见 [examples/docs](../examples/docs)。

---

## 4. 变更记录（CHANGELOG）

- **SHOULD**：按版本组织，条目分类：`新增` / `修复` / `变更` / `移除` / `破坏性变更`。
- **MUST**：破坏性变更在版本号（主版本递增）与 CHANGELOG 双重显式声明。
- **SHOULD**：协议/依赖升级条目注明影响面。

---

## 5. 工具与自动化

- **SHOULD**：使用 Javadoc 工具生成 API 参考（Java 部分）。
- **SHOULD**：HTTP API 用 OpenAPI 文件生成并接入 CI 校验（schema 变更即失败）。
- **SHOULD**：语言文件键完整性接入校验（比对 zh/en 键集），缺键即构建失败。
- **MAY**：格式检查（spotless）纳入构建，保持风格统一（主项目已配置 [spotless 配置](../GTLSUPBJAVA/spotless/spotless.eclipseformat.xml)）。

---

## 6. 检查清单

- [ ] 数据包/接口类注释含契约（触发、校验、回发/计算规则）；
- [ ] 注释中文、精简、说明"为什么"；
- [ ] 显示文案全部走语言文件，zh/en 键集一致；
- [ ] Tooltip 精简且说明机制；
- [ ] 对外 HTTP 有 OpenAPI 描述；
- [ ] CHANGELOG 分类记录，破坏性变更显式声明。
