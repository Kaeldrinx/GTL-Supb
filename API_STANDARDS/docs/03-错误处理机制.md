# 03 · 错误处理机制

> 目标：**单个错误不导致整体崩溃；错误对用户可见时是友好中文提示；错误对开发者可见时是可排查日志。**
> 分两套体系：模组运行时错误处理（主场景）与对外 HTTP 错误码（行业兼容，供扩展）。

---

## 1. 处理优先级

任何错误处理前先回答：**这个错误谁该知道？**

| 错误类型 | 处理方式 | 谁看到 |
| --- | --- | --- |
| 恶意/伪造请求（校验失败） | 静默忽略，不提示不响应 | 无人（防探测） |
| 用户可理解的业务失败 | 中文提示消息（i18n） | 玩家 |
| 环境异常（区块未加载、跨维度失败） | 降级占位 + 日志 | 开发者（日志） |
| 未知枚举/未知动作 | `default` 分支静默忽略 | 无人 |
| 真正的程序缺陷 | 日志 + 安全降级，不崩溃 | 开发者（日志） |

---

## 2. 模组运行时错误处理规则

### 2.1 校验失败 → 静默忽略

- **MUST**：服务端校验不通过（sender 为 null、containerId 不匹配、类型不符、归属不符）一律 `return`，不回包不提示，避免向攻击者泄露校验规则。
- **MUST**：`handle()` 结束时始终 `ctx.get().setPacketHandled(true)`，即使校验失败（否则网络线程空转）。

**项目正例**：[C2SWAPConnectionPacket.java](../GTLSUPBJAVA/src/main/java/com/gtlsupb/gtlsupb/network/C2SWAPConnectionPacket.java) 校验链逐级 `return`，`default -> {}` 忽略未知动作。

### 2.2 业务失败 → 中文提示

- **SHOULD**：可让用户理解的失败使用 `Component.translatable("modid.分类.语义")` 提示（如 `gtlsupb.wap.connection.cancel_failed`），文案走语言文件，禁止硬编码中文/英文字符串。
- **MUST**：提示类消息不做敏感信息泄露（坐标、内部状态）。

**项目正例**：同上一文件中 `player.displayClientMessage(...)` 的用法。

### 2.3 环境异常 → 降级 + 日志

- **MUST**：外部环境操作（读其他维度、区块加载、跨 mod 调用）用 try-catch 包裹并给出降级值。
- **MUST**：catch 后记录日志（`LOGGER.warn/error` 带上下文），禁止吞异常不留痕。
- **MUST NOT**：用空 catch 块静默吞掉程序缺陷类异常。

**项目正例**：[C2SWAPConnectionPacket.java](../GTLSUPBJAVA/src/main/java/com/gtlsupb/gtlsupb/network/C2SWAPConnectionPacket.java) `resolveBlockDisplayName` catch `Throwable` 返回 `"??"`（环境性降级；注释说明"避免强制加载区块带来副作用"）。

### 2.4 异常边界

- **MUST**：服务端 tick / 网络线程处理逻辑整体防护，单个机器/区块异常不得拖垮整个 tick。
- **SHOULD**：对临时性失败（资源竞争、跨服数据未就绪）提供重试或延迟自愈，而非直接失败。

## 3. 错误码体系（行业兼容，供 HTTP API 扩展）

### 3.1 错误码分类

| 段 | 区间 | 含义 |
| --- | --- | --- |
| 0 | 0 | 成功 |
| AUTH | 1000~1999 | 认证（身份无效、令牌过期） |
| FORBIDDEN | 2000~2999 | 授权（无权限、越权操作） |
| VALIDATION | 3000~3999 | 参数校验失败 |
| NOT_FOUND | 4000~4999 | 资源不存在 |
| CONFLICT | 5000~5999 | 状态冲突（重复提交、版本过期） |
| RATE_LIMIT | 6000~6999 | 限流 |
| INTERNAL | 9000~9999 | 服务端内部错误 |

### 3.2 错误响应 JSON

- **MUST**：错误响应统一结构（见 [examples/json/error.example.json](../examples/json/error.example.json)）：

```json
{
  "code": 3001,
  "message": "参数校验失败",
  "detail": "field 'questId' 不能为空",
  "traceId": "8f14e45f-ceea-47a9-9c2e-1f1e9c9c9c9c"
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| code | 是 | 业务错误码（0 为成功） |
| message | 是 | 人类可读中文摘要 |
| detail | 否 | 可排查的补充信息 |
| traceId | 是 | 链路追踪 ID，日志联动 |

### 3.3 HTTP 状态码映射

| HTTP 状态码 | 使用场景 |
| --- | --- |
| 200 | 成功 |
| 400 | VALIDATION |
| 401 | AUTH（未认证） |
| 403 | FORBIDDEN（已认证无权） |
| 404 | NOT_FOUND |
| 409 | CONFLICT |
| 429 | RATE_LIMIT |
| 500 | INTERNAL（不暴露堆栈给客户端） |

---

## 4. 日志规范

- **MUST**：日志级别选择：`info`（生命周期）、`warn`（可恢复异常）、`error`（程序缺陷/不可恢复）。
- **MUST**：日志带上下文（玩家、维度、坐标、关联 ID），便于回放定位。
- **MUST NOT**：日志输出密码、令牌、完整堆栈到客户端可见通道。
- **SHOULD**：模组统一 LOGGER（如 `GTLSupb.LOGGER`），禁止各文件自建 logger。

---

## 5. 检查清单

- [ ] 校验失败路径静默忽略且 `setPacketHandled(true)`；
- [ ] 业务失败走 i18n 中文提示，无硬编码文案；
- [ ] 环境异常有降级值 + 日志，无空 catch；
- [ ] 未知枚举走 default 静默分支；
- [ ] 日志带上下文、分级正确、无敏感信息。
