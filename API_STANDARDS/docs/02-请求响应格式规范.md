# 02 · 请求/响应格式规范

> 覆盖三种 API 形态：模组内部网络 API（C2S/S2C）、内部 Java API、对外 HTTP API。
> 核心要求：**格式统一、可序列化、可关联、可演进**。

---

## 1. 模组内部网络 API（C2S/S2C）

### 1.1 通道与注册

- **MUST**：使用 Forge `SimpleChannel`（`NetworkRegistry.newSimpleChannel`），模组内单通道集中注册。
- **MUST**：定义 `PROTOCOL_VERSION` 字符串并双向严格匹配（客户端/服务端版本不一致即拒绝连接）。
- **MUST**：注册顺序即 `nextId` 递增，同一 mod 内注册顺序不可随意调整（ID 变更破坏兼容）。
- **MUST**：每个数据包实现 `encode` / `decode` / `handle` 三个静态方法，并以方法引用注册。

**项目正例**：[GTLSupbNetworkHandler.java](../GTLSUPBJAVA/src/main/java/com/gtlsupb/gtlsupb/network/GTLSupbNetworkHandler.java)（14 个数据包集中注册）。

### 1.2 数据包结构约定

| 要素 | 约定 | 示例 |
| --- | --- | --- |
| 类名 | `C2S<业务><动作>` / `S2C<业务><状态>` | C2SWAPConnectionPacket、S2CWAPConnectionListPacket |
| 动作语义 | 具名常量，0 起递增 | `ACTION_QUERY_LIST = 0` |
| 字段 | final，构造器赋值，不可变 | `private final int containerId;` |
| 序列化 | 手写 `FriendlyByteBuf` 读写，读写顺序必须一致 | `buf.writeVarInt` / `buf.readVarInt` |
| 可空字段 | `writeBoolean(hasX)` + 条件读写 | 目标维度/坐标 |
| 关联 | 携带 `containerId`（菜单会话 ID）关联请求与响应 | C2S ↔ S2C 成对 |

### 1.3 请求-响应模式

一次完整交互的标准链路（详见 [07-最佳实践示例](07-最佳实践示例.md) 案例一）：

```
客户端 UI 动作
  → 构造 C2S 请求包（携带 containerId + 业务字段）
  → 服务端 handle()：
      enqueueWork 中按顺序校验：身份 → 会话 → 类型 → 归属
      → 校验失败：静默忽略 或 回发失败提示
      → 校验通过：执行业务
  → 需要结果时：CHANNEL.send(PacketDistributor.PLAYER.with(() -> player), S2C 响应包)
  → 客户端 handle()：更新 UI / 打开屏幕
```

- **MUST**：请求-响应用 `containerId`（或等价关联键）绑定，避免乱序错配。
- **MUST**：响应包必须携带与请求一致的关联键。
- **MUST**：服务端回发用 `PacketDistributor.PLAYER.with(() -> player)` 定向，禁止无差别广播可定向的数据。

**项目正例**：[C2SWAPConnectionPacket.java](../GTLSUPBJAVA/src/main/java/com/gtlsupb/gtlsupb/network/C2SWAPConnectionPacket.java) `handleQueryList` 回发 [S2CWAPConnectionListPacket.java](../GTLSUPBJAVA/src/main/java/com/gtlsupb/gtlsupb/network/S2CWAPConnectionListPacket.java)。

### 1.4 双端职责划分

- **服务端（C2S handle）**：校验 + 执行业务 + 回发结果。**MUST** 在 `ctx.get().enqueueWork()` 内执行，结束时 `ctx.get().setPacketHandled(true)`。
- **客户端（S2C handle）**：仅更新 UI / 播放效果 / 打开屏幕。**MUST NOT** 在客户端做权威状态修改。

## 2. 内部 Java API

### 2.1 方法签名规范

- **MUST**：方法名以动词开头，返回语义明确（`get`/`is`/`compute`/`build`）。
- **SHOULD**：可空返回值用 `Optional`；集合返回不可变视图或空集合，不返回 null。
- **MUST**：对外可见的公开方法必须有 Javadoc，说明入参约束与返回值语义。
- **SHOULD**：复杂计算入口单一（如 [RecipeCalculationHelper.java](../GTLSUPBJAVA/src/main/java/com/gtlsupb/gtlsupb/utils/RecipeCalculationHelper.java) 的 `GetMaxParallelForRecipeFunction` 等函数式拆分）。

### 2.2 能力接口规范（核心）

- **MUST**：能力接口单方法/最小方法组（ISP），方法名直述语义。
- **MUST**：接口 Javadoc 写明能力来源、计算规则与边界值（如"批处理倍率：未开启返回 1，开启返回配置上限内可适应的最大倍率"）。
- **MUST**：能力通过 `PartAbility` 常量 + 能力接口双通道暴露：`PartAbility` 供结构识别，接口供逻辑调用。

**项目正例**：
- [ILimitedDurationMachine.java](../GTLSUPBJAVA/src/main/java/com/gtlsupb/gtlsupb/api/machine/ILimitedDurationMachine.java)（默认方法 + 契约注释）；
- [IBatchProcessingMachine.java](../GTLSUPBJAVA/src/main/java/com/gtlsupb/gtlsupb/api/machine/IBatchProcessingMachine.java)（能力方法组 + 语义注释）。

### 2.3 事件机制

- **SHOULD**：允许外部扩展点使用事件（如 [EnforcerPanelEvents.java](../GTLSUPBJAVA/src/main/java/com/gtlsupb/gtlsupb/common/EnforcerPanelEvents.java)），事件命名 `XxxEvents`，可携带注册回调。

## 3. 对外 HTTP API（行业兼容，供扩展）

> 当未来需要对外 HTTP 服务时，按本节对齐行业规范；内部 JSON 序列化也复用此风格。

### 3.1 URL 与资源命名

- **MUST**：资源名一律小写复数名词：`/api/v1/quests`、`/api/v1/connections`。
- **MUST**：路径层级表达从属关系：`/api/v1/players/{playerId}/connections`。
- **MUST NOT**：URL 中出现动词（用 HTTP 方法表达动作），除非是 RPC 型端点。

### 3.2 HTTP 方法语义

| 方法 | 语义 | 幂等 |
| --- | --- | --- |
| GET | 查询（只读） | 是 |
| POST | 创建 / 触发动作 | 否（可配幂等键） |
| PUT | 全量替换 | 是 |
| PATCH | 部分更新 | 否 |
| DELETE | 删除 | 是 |

### 3.3 JSON 响应格式

- **MUST**：成功响应使用统一 envelope（可含 `data` 与 `meta`）：

```json
{
  "code": 0,
  "message": "ok",
  "data": { "questId": "q_001", "status": "completed" },
  "meta": { "requestId": "8f14e45f-ceea-47a9-9c2e-1f1e9c9c9c9c" }
}
```

- **MUST**：错误响应遵循 [03-错误处理机制](03-错误处理机制.md) 的错误 JSON 结构。
- **MUST**：时间戳使用 ISO 8601（`2026-09-13T10:00:00Z`）；金额/能量等数值用整数或定点（long），禁止浮点。
- **SHOULD**：列表接口支持 `page`/`pageSize` 分页与 `meta.total`。

### 3.4 字段命名与序列化约定

- **MUST**：JSON 字段 snake_case；Java 侧 DTO 字段 camelCase 并通过注解映射（如 Jackson `@JsonProperty`）。
- **SHOULD**：DTO 不可变（final 字段 + 构造器），序列化器显式注册。

---

## 4. 格式检查清单

- [ ] 数据包命名符合 `C2S/S2C + 业务 + 动作/状态`；
- [ ] 字段读写顺序一致、可空字段有 has 标记；
- [ ] 请求与响应携带一致的关联键（containerId）；
- [ ] 服务端逻辑在 `enqueueWork` 内、结束时 `setPacketHandled(true)`；
- [ ] 回发使用定向 `PacketDistributor`；
- [ ] 能力接口最小、有契约注释；
- [ ] JSON 字段 snake_case、时间 ISO 8601、数值不用浮点。
