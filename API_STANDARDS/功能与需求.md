本文件记录**用户已确认**的需求与规格，按日期追加，不删除历史条目（`执行规则.md` 规则 4/20）。

条目类型：

- **【需求】** 用户明确要求的交付内容；
- **【定位】** 用户确认的项目定位与边界；
- **【约束】** 用户设定的禁止项或限制条件；
- **【规格】** 已确认的具体功能规格（数值、结构、行为）。

## 一、项目定位与边界

### 【定位】GTLsupb 模组

- Minecraft 1.20.1 Forge 的 GTCEu 1.4.4 生态**附属模组**（MOD ID `gtlsupb`）。
- 定位：为 GTCEu / gtlcore / AE2 生态提供**高端多方块机器**与**跨模组集成**功能。
- 核心机制方向：跨配方并行、批处理、零能耗、模块化主机、无线能量/无线 AE、AE 合成样板驱动。

### 【约束】UI 与文本（用户偏好，持续有效）

- 所有 GUI 文本、Tooltip、提示消息一律**中文**（语言文件 `zh_cn.json` + `en_us.json` 双语，键集一致）。
- Tooltip **精简、说明机制**，不做冗余或显而易见的提示。
- 配置界面（如批处理面板、配置注释）**直接显示中文**，不依赖悬停查看中文。
- 新增功能配置项**优先放配置文件**（`ConfigHolder`），除非用户明确要求放 GUI。

### 【约束】技术方案取舍（用户偏好）

- 性能优化优先**低风险、零额外开销**的方案，不引入新的效率问题。
- 功能范围优先 **GTM/gtlcore 机器专属功能**，不做针对所有方块的通用改动。
- 与参考工程（gtlcore / gtladditions / GTLUltimate）对比实现时，先核对版本适用性，只借鉴设计不照搬代码（`执行规则.md` 规则 9）。

## 二、已确认的需求

### 【需求】批处理功能（侧边栏开关 + 自适应倍率）

- 支持批处理的机器在侧边栏提供批处理开关（`BatchProcessingFancyConfigurator`，金粉=关 / 金粒=开）。
- 倍率不再手动调节，由配置文件 `adaptiveBatchMax`（默认 100）控制；开启后机器**按输入/输出自动降档**，实际倍率最高不超过该值。
- 批处理语义（gtlcore）：内容 ×N、耗时 ×N，EU/秒 维持并行基准不放大；输入不足整倍额批次时自动降档而非卡死（3.4.beta.9 实现为 `RecipeCalculationHelper.findFeasibleBatch` 折半搜索）。

### 【需求】跨配方并行机器

- 多类型机器搜索全部配方类型，把同批匹配配方合并为一条配方处理（`MutableRecipesLogic`）。
- 并行分配支持 FAIR / GREEDY 两种算法。
- 合并配方输入必须保证可一次取齐：多配方复用同一批原料时，放不下的配方让位于先入列配方，**不得误报「材料输入不足」**（3.4.beta.9 修复）。

### 【需求】零能耗机器

- 零能耗多类型机器（`ZeroEnergyMultiTypeMachine` 系）：不消耗 EU，跳过配方条件，无限并行（受输入物品数限制）。
- 处理时间由玩家通过运行速率调控器设定（`ILimitedDurationMachine`，默认 20t，1~200t）。
- 支持批处理（同上）。

### 【需求】模块化主机

- `MicrocosmFoundry`：4 个模块位，产出倍率 = 已成型模块数 ×20（永恒模块时锁定为配置值，默认 100）。
- `SuperStellarWorldForgingHeavenShip`：类似模块化主机（奇点模块锁定倍率默认 100）。
- 主机倍率只放大产出、**不放大输入需求**（避免整批失败不启动）。

### 【需求】蒸汽能系统

- `SteamUniversalModule`：独立无线蒸汽能版本，通过 Data Stick 绑定 UUID 从无线蒸汽能电网消耗蒸汽。
- 不限制电压等级，所有配方统一 1 tick 完成；并行 = 连接数 ×16384。
- 蒸汽能机器无 EU 输入（移除 `MAX_VOLTAGE` 电压上限约束）。

### 【需求】AE2 集成

- **ME 无线访问点（WAP）无线连接**：基于 AE2 WAP（`appliedenergistics2-forge-15.2.1.jar`）扩展无线连接能力，配置开关 `enableWapWireless`（默认 true）。
- **AE 终端快捷键跳转**：默认键 `G` / `V`，从终端界面跳转到可合成样板所在方块并打开其 GUI。
- **AE 合成样板驱动的样板总成**：基于 gtlcore `MEPatternBufferPartMachine` 的机制（超限样板总成 `OverlimitStockingPatternBufferPartMachine`），支持样板输入/虚拟执行链/配方反查。

### 【需求】AE2-FTB Quests 集成（默认启用）

- AE2-FTB Quests 任务提交功能**默认启用**。
- 任务提交 GUI **只能通过快捷键打开**，删除命令打开方式。
- 提交开关**放在 GUI 内**（不放配置文件）。

### 【需求】FTB Chunks 联动

- 无线能量广播（超维能量稳定枢纽、虚空能量发生器）**只面向 ftb-chunks 强制加载的区块**及其维度广播。
- 无线广播前**先检查方块能否注入 EU**，再绑定其 UUID（避免性能浪费）。

### 【需求】配方处理细节

- `checkRecipe()` 使用 `RecipeRunnerHelper.matchRecipe(machine, recipe)`：保留输入匹配，跳过配方条件检查。
- 无连接时 `getMaxParallel()` / `maxParallel()` 返回 **16384**。
- 配方反查标签（`PatternRecipeSearchHelper`）严格匹配：输入输出数量完全一致才标标签，歧义时返回无标签，防止误标。
